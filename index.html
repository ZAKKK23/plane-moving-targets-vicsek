plane-moving-targets (aligned, Vicsek)

A Vicsek-model agent simulation with moving targets, ported from MATLAB to a dependency-light browser build.

Vicsek model metric-radius alignment + noise aligned straight-line + asymmetric sinusoidal target motion MATLAB + JS ports no build step

The target scenario is unchanged from the earlier VTP version of this project: you choose a number of straight-line targets (0-5), each on its own fixed-height horizontal lane, plus one target that's always added on top and oscillates asymmetrically in y — descending at angular frequency q and rising back up at n×q (n times faster). Every target shares a single horizontal speed and a single shared x-coordinate, so they're aligned (exactly the same x) at every instant.

What's different here is the agent dynamics. Instead of the VTP model (Voronoi/Delaunay-neighbor repulsion + alignment + homing, with a Voronoi-cell-based speed governor), agents follow the classical Vicsek model:

  • Neighbors are metric, not topological: every agent within a fixed radius R — no Delaunay triangulation, no Voronoi cells anywhere.
  • Each agent's new heading is the vector-average heading of its neighbors (including itself) — the textbook Vicsek consensus rule.
  • A uniform random angular kick of size η is added every step — the classic Vicsek noise parameter that drives the order/disorder transition.
  • Every agent moves at the same constant speed every step. There's no crowding-based speed governor, because there are no Voronoi cells to measure.

Since bare Vicsek has no notion of a target at all, homing toward the nearest target is kept as an extension: each agent's heading is a blend of the neighbor-consensus direction and the direction to its nearest target, weighted by ν — the same role ν always played, just blending two directions instead of three forces.

Two implementations, one model

  • index.html (this page, live simulation tab) — a plain JavaScript/Canvas port that runs directly in the browser, no install, no external libraries at all.
  • matlab/dynamics.m — the original MATLAB implementation, browsable under the matlab version tab.

MATLAB version

The original implementation, in matlab/.

Requires base MATLAB only — no toolboxes at all (the pairwise-distance computation is plain broadcasting, not pdist/squareform, so it doesn't even need the Statistics Toolbox). Run:

cd matlab
matlab -r dynamics

...or open dynamics.m in the MATLAB editor and run it. You'll be prompted for the number of straight-line targets (0–5); one asymmetrically-oscillating target is always added on top. An interactive figure then opens with a control panel (agents' constant speed v0, ν, R, η, shared horizontal speed, each straight target's height, and the oscillating target's height/amplitude/q/n — Apply / Pause / Reset Targets).

This folder only ships three MATLAB files: dynamics.m, Target.m (generic target geometry, not Voronoi-specific), and nearestOnSegment.m (a small helper Target.m depends on). Every VTP-only file — neighborhoods.m, alignTo.m, transition.m, voronoiProjectToBoundary.m, and the Voronoi-diagnostic utilities — is gone, since none of them are used or meaningful once the dynamics are Vicsek.
